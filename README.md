# 漂移时钟校时 · 可追溯时间轴模拟系统

两台本地设备模拟器同时上传测量片段，各自时钟存在漂移，校时记录可能迟到。
本系统在**不接真实硬件**的前提下，完整演示「原始时间保存 → 校时计算 →
版本化发布」的全链路，并严格区分**到达顺序**与**真实先后**。

仅依赖 Python 3.11 标准库，前端为原生 HTML/CSS/JS，无任何第三方包。

## 启动

```bash
python3 -m timesync                      # 默认端口 8000，常规漂移场景
python3 -m timesync --port 8123 --scenario midnight   # 跨午夜场景
python3 -m timesync --scenario extreme   # 强漂移 + 高网络乱序
bash run.sh                              # 等价的便捷脚本
```

打开 `http://127.0.0.1:8000/`，页面每秒自动刷新。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

20 个用例覆盖：插值/外推/无校时映射、不确定度增长、不可排序边界、
重启复用序号、旧计算结果晚到的版本栅栏、局部重算 vs 整段重建、
发布版不可变自洽、跨午夜标记、HTTP 端到端冒烟。

## 架构与数据流

```
 DeviceSimulator A          DeviceSimulator B
 (分段漂移 DeviceClock)      (分段漂移 DeviceClock)
        │  测量片段(设备时间, seq, boot_epoch)
        ▼  经模拟网络延迟（可乱序到达）
 ┌─────────────────────────────────────────────┐
 │ Receiver 接收服务                             │
 │  · 原始记录只追加、不可变                      │
 │  · 盖 arrival_time 与全局 arrival_seq（仅审计）│
 │  · 校时记录同样只追加，允许迟到补校             │
 └─────────────────────────────────────────────┘
        │ on_change 触发（线程安全，锁外回调）
        ▼
 ┌─────────────────────────────────────────────┐
 │ Calculator 校时计算器（独立线程 + 计算线程池）  │
 │  · 分段线性映射：插值 / 外推 / uncalibrated    │
 │  · 不确定区间随外推距离扩大                    │
 │  · 局部重算 or 整段重建，决策写入版本元数据     │
 │  · 暂停/恢复；版本栅栏拒绝迟到的旧作业          │
 └─────────────────────────────────────────────┘
        │ on_version（候选版本，不可变快照）
        ▼
 ┌─────────────────────────────────────────────┐
 │ Publisher 入库端                              │
 │  · 只发布“已确认”版本（自动确认可关，转手动）   │
 │  · 版本号单调栅栏，旧版本无法回退发布版         │
 └─────────────────────────────────────────────┘
```

## 关键设计决策

### 1. 为什么不能用到达顺序冒充真实先后

接收服务给每条记录分配的 `arrival_seq` 只表示“我先看到谁”。两台设备的
片段经过不同的模拟网络延迟（常规场景 40–260ms，强漂移场景 80–900ms），
后发生的片段完全可能先到达。因此：

- 同设备同 boot 内：以设备本地**序号 seq** 为权威顺序（序号单调，不受网络影响）；
- 跨设备 / 跨 boot：只比较**校正后的不确定区间**，区间不重叠才能定先后；
- `arrival_seq` 仅用于审计，并在时间轴表格里计算“序差”列——非 0 即
  到达顺序与真实先后不一致的活实例。

### 2. 哪些边界无法可靠排序

时间轴对每一对相邻记录显式检测并输出两类边界（UI 顶部红/黄条展示）：

| 边界类型 | 触发条件 | 为什么无法排序 |
| --- | --- | --- |
| `overlap` | 两条记录的校正不确定区间相互重叠 | 漂移校正只能把真实时刻约束在区间内，区间重叠时谁先谁后在数学上不可判定 |
| `uncalibrated` | 相邻位置存在该 boot 尚无任何校时的记录 | 没有映射就没有校正时间与不确定区间，无法与任何记录比较 |

外推记录的不确定区间随距离校时点的长度按 PPM 扩大，距离越远越容易与
邻居产生 `overlap` 边界——区间宽度如实反映可信度，而不是隐藏不确定性。

### 3. 局部重算 vs 整段重建

计算器按 `(device_id, boot_epoch)` 分组，对比上一版本的校时点集合：

- **局部重算 `local_recompute`**
  - 新校时点严格落在两个已知校时点之间：只重算受影响区间
    `[左邻居设备时间, 右邻居设备时间]` 内的记录，其余校正结果原样复用；
  - 校时映射未变、只有新测量到达：仅对新记录做增量校正。
- **整段重建 `full_rebuild`**
  - 新 boot 分组首次构建；
  - 新增首/末校时点（改变外推区斜率）、批量补校等结构性变化。

每个版本的 `strategy`、`strategy_reason` 与 `recomputed_measurement_ids`
都随版本持久化，可在审计日志与版本摘要里追溯。

### 4. 旧计算结果晚到（版本栅栏）

计算作业带模拟耗时（部分作业随机 0.6–1.4s 长耗时），低水位作业可能比
高水位作业更晚完成。作业完成时：

- 若作业水位 ≤ 最近已接受版本水位 → **整版拒绝**，标记 `rejected` 并写
  审计 `calc_stale_rejected`，绝不覆盖更新结果；
- 入库端另有独立栅栏：手动推送旧版本号会被拒绝（`publish_stale_rejected`）。

### 5. 三个棘手场景如何保持发布版自洽

- **设备重启复用序号**：重启后 `boot_epoch +1`、seq 从 1 重新计数，
  记录唯一键是 `(device_id, boot_epoch, seq)`，复用 seq 不冲突；
  新 boot 在校时到达前全部 `uncalibrated` 并产生边界，补校后自动消解。
- **校时跨日期边界**：所有时间以 epoch 毫秒存储与计算，午夜只是表示层
  现象；设备读数已跨日而参考时钟未跨日的记录会被 `crosses_midnight`
  显式标记，校正结果仍落在参考时钟日期上。
- **旧计算结果晚到**：版本不可变 + 双栅栏（计算器水位栅栏、入库端版本号
  栅栏），任何已发布版本的记录、边界、校时依据都不会被后续数据悄悄改写。

## 网页可做的操作

1. 调整任一设备的漂移率（新增一段时钟折线，旧段保留，历史可复现）；
2. 暂停/恢复设备上传，重启设备（观察 boot 与序号复用）；
3. 即时校时，或一键补一条 20 秒前的迟到校时（观察局部重算/重建决策）；
4. 暂停计算器再恢复（观察作业排队、在途旧作业被栅栏拒绝）；
5. 关闭自动确认，手动选择候选版本入库；
6. 在「候选版 / 已发布版」两个标签间对比，查看不可排序边界、序差、
   隐藏真值误差与跨午夜标记；
7. 一键重置并切换三个场景预设。

## 目录结构

```
timesync/
  clocks.py       参考时钟、分段漂移设备时钟、设备模拟器
  model.py        测量/校时/校正记录/边界/版本 数据模型
  receiver.py     接收服务（原始记录 + 到达顺序，到达顺序不参与排序）
  calibration.py  分段线性映射、不确定区间、时间轴与边界检测（纯函数）
  calculator.py   计算器：暂停恢复、版本栅栏、重算策略
  publisher.py    入库端：已确认版本发布、单调栅栏
  app.py          组件编排、设备驱动线程、场景预设、审计日志
  server.py       HTTP API + 静态页服务
web/              单页控制台（原生 JS）
tests/            20 个 unittest 用例
```

## REST API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 全量快照（设备、原始记录、校时、作业、版本、审计） |
| GET | `/api/scenarios` | 场景预设列表 |
| POST | `/api/devices/rate` | 调整漂移率 |
| POST | `/api/devices/pause` `/resume` `/restart` | 设备控制 |
| POST | `/api/calibrations` | 新增校时（可指定历史时刻实现补校） |
| POST | `/api/calculator/pause` `/resume` | 计算器暂停/恢复 |
| POST | `/api/publisher/auto` | 开关自动确认 |
| POST | `/api/publisher/confirm` | 手动确认当前候选版本 |
| POST | `/api/reset` | 重置系统并切换场景 |
